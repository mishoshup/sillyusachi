## 1. Finding Validation: Oracle's 5 Bugs

### Bug 1: Dual Snap Points (['start', 'end'] with lock type)
**Verdict: ✅ VALIDATED — PRIMARY CAUSE OF BROKEN SCROLL**

Evidence (scroll-snap.js lines 35-37):
```
sections.forEach((section) => {
  snap.addElement(section, {
    align: ['start', 'end'],
  });
});
```

With type: 'lock', each section gets TWO lock targets. For viewport-height sections this creates a double-tap feel (the two points are nearly coincident). For tall sections (CommissionInfo), the start and end diverge, causing unpredictable jumps. The workaround in onSnapComplete (Math.floor(index / 2)) is a symptom, not a fix — it tells us the architecture is fighting itself.

**Fix**: Single align: 'start' per section. No dual points. No index division hack.

---

### Bug 2: wrapper === content (Zero Scroll Delta)
**Verdict: ✅ VALIDATED**

Evidence (scroll-snap.js lines 17-20):
```
const lenis = new Lenis({
  wrapper,       // <main> element
  content: wrapper,  // SAME <main>
  ...
});
```

Lenis works by applying a transform: translateY() to the **content** element. When wrapper === content:
- Lenis cannot reliably measure the scroll delta because translating the wrapper displaces its own viewport
- Svelte's h-[100dvh] on <main> creates an ambiguous dimension state
- Scroll height calculations become unreliable because wrapper.scrollHeight === wrapper.clientHeight (both are 100dvh)

The Lenis docs explicitly show separate wrapper and content. This is basic architecture.

**Fix**: `<main>` = wrapper, insert an inner `<div id="lenis-content">` = content child.

---

### Bug 3: Layout overflow-hidden Creates Inherited Clip Chain
**Verdict: ✅ VALIDATED — BLOCKING BUG**

Evidence (+layout.svelte line 13):
```
<div class="h-[100dvh] overflow-hidden bg-[#080612] bg-cover bg-fixed">
```

The layout wrapper has overflow-hidden which clips ALL children to exactly viewport height. The <main> element is h-[100dvh] inside it — it fits exactly within the clipped parent. Nothing can overflow. Lenis has zero space to scroll.

Even without Lenis, this prevents CSS scroll-snap or any form of scrolling. The layout acts as a rigid clipping mask.

**Safe to remove because**: All children that should remain fixed use position: fixed (GlitterOverlay, Haze overlays, Nav sidebar, Music player). <main> will establish its own scroll context.

**Fix**: Remove overflow-hidden from the layout div.

---

### Bug 4: Height Measurement Race
**Verdict: ✅ VALIDATED — TIMING ISSUE**

Evidence (scroll-snap.js):
- setupLenis() is called from onMount in +page.svelte
- Snap positions are calculated immediately using addElement() (line 36)
- Sections use min-h-[100dvh] — actual heights depend on content (images, fonts, component expansion)

The Snap library takes a snapshot of element positions at init time. If fonts haven't loaded, images haven't rendered, or Svelte reactive content hasn't expanded, the initial section heights are wrong. The debounce: 500 on resize handles window resizing but NOT content-driven height changes.

There's no ResizeObserver to re-measure sections when their content loads. This means snap positions are calculated against potentially wrong heights.

**Fix**:
- Use ResizeObserver on each section to invalidate snap positions when heights change
- Defer RAF start by one frame to ensure one layout pass completes first

---

### Bug 5: RAF Lifecycle Race
**Verdict: ✅ VALIDATED — SEQUENCING ISSUE**

Evidence (scroll-snap.js lines 51-54):
```
function raf(time) {
  lenis.raf(time);
  requestAnimationFrame(raf);
}
requestAnimationFrame(raf);  // Starts IMMEDIATELY on same tick as Svelte onMount
```

requestAnimationFrame fires **before** browsers typically complete layout and paint for that frame. When called from onMount, the RAF fires before Svelte has fully laid out all sections and computed their final positions. Lenis captures 0 or partial scroll height on its first frames, recording impossible snap positions.

The correct pattern: **double-RAF** or **microtask defer** to ensure one full layout/paint cycle completes before Lenis initializes.

**Fix**:
```
// Defer RAF start to after next frame's layout completes
requestAnimationFrame(() => {
  requestAnimationFrame(startRaf);
});
```

## 2. Enterprise Lenis Architecture

### Architecture Overview

```
[Layout wrapper: <div>]                   ← NO overflow-hidden, plain block
   │
   ├─ [GlitterOverlay]                    ← position: fixed, z-0
   ├─ [Haze overlays]                     ← position: fixed, z-0
   ├─ [Nav sidebar]                       ← position: fixed, z-50
   ├─ [Music player]                      ← position: fixed, z-50
   │
   └─ [MAIN: <main>]                      ← Lenis WRAPPER
       │   overflow: hidden (explicit)
       │   height: 100dvh
       │   touch-action: none (Lenis handles gestures)
       │
       └─ [<div id="lenis-content">]      ← Lenis CONTENT (gets transform)
           │
           ├─ <section data-page="0">     ← snap-align: start, min-h-[100dvh]
           │   └─ <Portfolio />
           │
           ├─ <section data-page="1">     ← snap-align: start, min-h-[100dvh]
           │   └─ <CommissionInfo />      ← TALL section: free scroll inside
           │
           └─ <section data-page="2">     ← snap-align: start, min-h-[100dvh]
               └─ <AboutMe />
```

### Lenis Config (Recommended)

```javascript
const lenis = new Lenis({
  wrapper,              // <main> element
  content,              // <div id="lenis-content"> — CHILD of wrapper
  duration: 1.2,
  easing: (t) => Math.min(1, 1.001 - Math.pow(2, -10 * t)),
  orientation: 'vertical',
  gestureOrientation: 'vertical',
  smoothWheel: true,
  syncTouch: true,      // critical for mobile
});
```

Rationale:
- wrapper !== content — proper scroll delta calculation
- easing: exponential-out — smooth deceleration matching current aesthetic
- duration: 1.2 — matches current, provides deliberate feel
- syncTouch: true — critical for mobile: syncs touch scroll with Lenis animation

### Snap Strategy

```javascript
const snap = new Snap(lenis, {
  type: 'proximity',     // NOT 'lock' — allows free scroll within tall sections
  debounce: 100,         // reduced from 500 — faster responsiveness
  lerp: 0.08,            // keep: smooth snap interpolation
  duration: 0.6,         // slightly faster than before (was 0.8)
});

// Single snap point per section
sections.forEach((section) => {
  snap.addElement(section, {
    align: 'start',       // ONE snap point, not ['start', 'end']
  });
});
```

**Why proximity over mandatory or lock:**

| Type     | Behavior                                                      | Tall Section Risk                                           |
|----------|---------------------------------------------------------------|-------------------------------------------------------------|
| lock     | Locks to nearest snap point, cannot scroll past               | User trapped at section start — cannot see tall content     |
| mandatory| Snaps to nearest when scrolling stops                         | User starts scrolling and stops — auto-snaps may trap mid   |
| proximity| Snaps only when within threshold                              | SAFEST: free scroll within tall sections, snaps at edges    |

CommissionInfo can grow tall (7+ sections of commission info). proximity ensures the user can scroll through its full content, only snapping when they slow down near the top/bottom of a section.

**Trade-off**: proximity means the snap is less aggressive — user can stop between sections if they scroll very slowly. With 3 sections at viewport height, the proximity threshold (40% default) makes this unlikely.

### Nav Tracking Strategy

Combined approach: Lenis scroll events + Snap completion

```javascript
// 1. Real-time nav update from scroll position
lenis.on('scroll', ({ scroll, limit }) => {
  const viewportThreshold = window.innerHeight * 0.3;
  let currentIdx = 0;
  sections.forEach((section, i) => {
    const rect = section.getBoundingClientRect();
    if (rect.top <= viewportThreshold) {
      currentIdx = i;
    }
  });
  if (currentIdx !== lastPage) {
    lastPage = currentIdx;
    onPageChange(currentIdx);
  }
});

// 2. Precise snap completion as confirmation
snap.onSnapComplete = ({ index }) => {
  // With single align points, index directly maps to section index
  onPageChange(index);
};
```

Why both? Scroll events → real-time nav highlight (updates as user scrolls). Snap completion → precise final state (catches edge cases where scroll event half-triggers). Threshold of 0.3 (30% viewport) prevents flickering during smooth scroll.

### Programmatic Scroll (Nav Buttons)

```javascript
function scrollToPage(index) {
  snap.goTo(index);  // Direct index — no multiply-by-2 needed
}
```

### Section Height Re-measurement (Anti Bug 4)

```javascript
const resizeObserver = new ResizeObserver(() => {
  snap.resize();
});
sections.forEach((section) => resizeObserver.observe(section));
```

This catches: font loading, images rendering, dynamic content updating inside CommissionInfo, window resize (backup to debounced listener).

### RAF Sequencing (Anti Bug 5)

```javascript
// Proper lifecycle: wait for Svelte layout to complete
const initRafId = requestAnimationFrame(() => {
  // First RAF: Svelte has mounted but layout may not be complete
  requestAnimationFrame(() => {
    // Second RAF: layout is now complete, safe to start Lenis
    function raf(time) {
      lenis.raf(time);
      requestAnimationFrame(raf);
    }
    requestAnimationFrame(raf);
  });
});
```

This ensures at least one full layout/paint cycle completes before Lenis takes its first measurement.

### Cleanup

```javascript
return {
  cleanup: () => {
    window.removeEventListener('resize', onResize);
    resizeObserver.disconnect();
    if (initRafId) cancelAnimationFrame(initRafId);
    if (rafId) cancelAnimationFrame(rafId);
    snap.destroy();
    lenis.destroy();
  },
  scrollToPage,
};
```

### Scrollbar Hiding

Already present in both app.css and +page.svelte:
```css
main::-webkit-scrollbar {
  display: none;
}
```

With Lenis managing scroll, the <main> element has overflow: hidden, so scrollbars won't appear anyway. The CSS is a harmless safety net.

## Appendix A: Complete scroll-snap.js Replacement

```javascript
import Lenis from 'lenis';
import Snap from 'lenis/snap';
import 'lenis/dist/lenis.css';

/**
 * Enterprise-grade Lenis smooth scroll with snap for mixed-height sections.
 *
 * Solves 5 known bugs:
 *  1. Dual snap points -> single 'start' per section
 *  2. wrapper === content -> separate wrapper (main) and content (#lenis-content)
 *  3. Layout overflow-hidden -> removed from parent (handled in +layout.svelte)
 *  4. Height measurement race -> ResizeObserver on each section
 *  5. RAF lifecycle race -> double-RAF defer on init
 *
 * @param {HTMLElement} wrapper - the scroll wrapper (<main>)
 * @param {(page: number) => void} onPageChange - callback for nav tracking
 * @returns {{ cleanup: () => void, scrollToPage: (index: number) => void }}
 */
export function setupLenis(wrapper, onPageChange) {
  // 1. Find content and sections
  const content = wrapper.querySelector('#lenis-content');
  if (!content) {
    console.error('[Lenis] #lenis-content not found inside wrapper');
    return { cleanup: () => {}, scrollToPage: () => {} };
  }

  const sections = Array.from(content.querySelectorAll('[data-page]'));
  if (sections.length === 0) {
    console.warn('[Lenis] No [data-page] sections found');
  }

  // 2. Init Lenis with wrapper !== content
  const lenis = new Lenis({
    wrapper,              // <main> — Lenis manages overflow: hidden
    content,              // #lenis-content — Lenis applies transform
    duration: 1.2,
    easing: (t) => Math.min(1, 1.001 - Math.pow(2, -10 * t)),
    orientation: 'vertical',
    gestureOrientation: 'vertical',
    smoothWheel: true,
    syncTouch: true,
  });

  // 3. Init Snap with proximity
  const snap = new Snap(lenis, {
    type: 'proximity',    // Allows free scroll within tall sections
    debounce: 100,        // Reduced for responsive updates
    lerp: 0.08,
    duration: 0.6,        // Slightly faster snap animation
  });

  // Single snap point per section
  sections.forEach((section) => {
    snap.addElement(section, {
      align: 'start',     // ONE point per section
    });
  });

  // 4. Nav Tracking
  let lastPage = -1;

  // Real-time tracking via scroll events
  lenis.on('scroll', () => {
    const viewportThreshold = window.innerHeight * 0.3;
    let currentIdx = 0;

    for (let i = 0; i < sections.length; i++) {
      const rect = sections[i].getBoundingClientRect();
      if (rect.top <= viewportThreshold) {
        currentIdx = i;
      }
    }

    if (currentIdx !== lastPage) {
      lastPage = currentIdx;
      onPageChange(currentIdx);
    }
  });

  // Precise tracking via snap completion
  snap.onSnapComplete = ({ index }) => {
    if (index !== lastPage) {
      lastPage = index;
      onPageChange(index);
    }
  };

  // 5. RAF Loop with Double-Defer (Anti Bug 5)
  let rafId = null;

  function startRaf() {
    function raf(time) {
      lenis.raf(time);
      rafId = requestAnimationFrame(raf);
    }
    rafId = requestAnimationFrame(raf);
  }

  const initRafId = requestAnimationFrame(() => {
    requestAnimationFrame(startRaf);
  });

  // 6. ResizeObserver per section (Anti Bug 4)
  const resizeObserver = new ResizeObserver(() => {
    snap.resize();
  });
  sections.forEach((section) => resizeObserver.observe(section));

  // 7. Window Resize (backup)
  const onResize = () => snap.resize();
  window.addEventListener('resize', onResize);

  // 8. Programmatic Scroll
  function scrollToPage(index) {
    if (index >= 0 && index < sections.length) {
      snap.goTo(index);   // Direct index — no * 2 hack
    }
  }

  // 9. Cleanup
  return {
    cleanup: () => {
      window.removeEventListener('resize', onResize);
      resizeObserver.disconnect();
      if (initRafId) cancelAnimationFrame(initRafId);
      if (rafId) cancelAnimationFrame(rafId);
      snap.destroy();
      lenis.destroy();
    },
    scrollToPage,
  };
}
```
